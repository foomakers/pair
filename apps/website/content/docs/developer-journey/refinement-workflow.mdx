The **analysis and refinement workflow** is the first of the two [lifecycle](/docs/developer-journey) workflows. It ends where the [delivery workflow](/docs/developer-journey/delivery-workflow) begins: at a story in the `Ready` [macrostate](/docs/concepts/canonical-states).

![Analysis and refinement workflow: brainstorm, stories, refine, breakdown, Ready, in three modes](/diagrams/refinement-workflow.svg)

*Figure: one idea reaches Ready in four steps; the three modes differ in who runs them.*

## The four steps

| Step | Skill | Result |
| --- | --- | --- |
| Brainstorm | `/pair-process-brainstorm`, with a `/pair-capability-grill` interview | a Draft epic and story tree from a theme |
| Stories | `/pair-process-plan-stories`, which triages each candidate (EXTEND or CREATE) | INVEST-valid Draft stories |
| Refine | `/pair-process-refine-story` | acceptance criteria, analysis, sizing, `## Assumptions` and `## Open Questions` |
| Breakdown | `/pair-process-plan-tasks` | tasks, dependency graph, AC coverage; the card becomes Ready |

Refinement opens with a **sync phase 0**: `/pair-capability-grill` asks one question at a time until you and the AI agree. Whatever the AI had to assume, or could not resolve, is written to the card as Assumptions and Open Questions. Detail: [Iteration](/docs/developer-journey/iteration#step-6-refine-a-user-story).

## Per mode

### Assisted

You run each skill by hand and read each output. Use it while learning pair or for high-risk work. Tutorials: [Brainstorming](/docs/tutorials/brainstorming), [Refinement](/docs/tutorials/refinement).

### Semi-automatic

You steer, a batch runs. `/pair-refine-batch` refines a set of Draft cards; `pair-cli run --until ready` stops each card right after the refinement phase, before implementation. Grill questions still reach you.

**With the CLI:** `pair-cli run --card 217 --prepare never --until ready`. **With `/pair-assistant` (optional, Claude Code):** CLI only for the run; ask [`/pair-assistant`](/docs/reference/pair-assistant#how-to-ask) to set the gate.

### Automatic

The `prepare` [autonomy gate](/docs/tutorials/automated-development#autonomy-until-gates-escalation) lets pair refine a Draft card alone. `never` proceeds and records assumptions on the card; `when` proceeds unless a condition escalates. An escalation keeps the card Draft, labels it `needs-review` and exits non-zero, so a human takes over. Default is `always`: a human prepares. Every key: [Adoption settings](/docs/reference/adoption-settings#techautomationmd).
