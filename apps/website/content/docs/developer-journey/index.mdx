pair defines a structured development lifecycle with **four levels** and **nine steps**. Each level builds on the previous, taking a project from initial idea to production-ready code.

The lifecycle is not rigid — you enter at whatever level matches your project's current state. But every one of the nine steps has a specific how-to guide and a matching skill that the AI follows, ensuring consistency and completeness.

Ahead of the nine steps sits one **optional entry point**: `/pair-process-brainstorm` — structured discovery (interview → domain → triage) that turns a rough theme, or an existing epic/story, into an integrated Draft epic/story tree the levels below then plan and build. It is human-initiated, never modifies the PRD, and is deliberately the one process skill without a numbered how-to guide.

## Let /pair-next Guide You

You don't need to memorize this sequence. Run `/pair-next` at any point and pair reads your project state — open issues, story statuses, task progress — to suggest the right next step. This is the recommended way to navigate the process.

```text
/pair-next
```

**When to use it:** at the start of every session, after completing a step, when switching context, or when you're not sure what to work on next.

## The Four Levels

```text
Discovery (optional, before Level 1) ─── /pair-process-brainstorm

Level 1: Induction (one-time)
  Step 1  Create PRD ─────────────── /pair-process-specify-prd
  Step 2  Bootstrap Project ──────── /pair-process-bootstrap
  Step 3  Plan Initiatives ────────── /pair-process-plan-initiatives

Level 2: Strategic Planning (per initiative)
  Step 4  Break Down Epics ────────── /pair-process-plan-epics

Level 3: Iteration (per epic)
  Step 5  Break Down Stories ──────── /pair-process-plan-stories
  Step 6  Refine Stories ──────────── /pair-process-refine-story
  Step 7  Create Tasks ────────────── /pair-process-plan-tasks

Level 4: Execution (per story)
  Step 8  Implement ───────────────── /pair-process-implement
  Step 9  Code Review ─────────────── /pair-process-review
```

You can follow this flow in two ways:

1. **Process Skills (recommended)** — invoke a slash command and the AI handles the structured process for you. See the [Skills Catalog](/docs/reference/skills-catalog) for all 51 skills.
2. **How-to Guides** — follow the manual step-by-step instructions from the Knowledge Base. See the [Guidelines & How-To Catalog](/docs/reference/guidelines-catalog) for all 9 how-to guides.

Skills compose capability skills internally, enforce adoption compliance, and update your PM tool automatically. The how-to guides give you the same process with full manual control.

The detailed walkthrough for each level is in the pages that follow.

## The Risk-Driven Flow

Behind the nine steps runs one thread: every story carries a **risk tier**, and the tier decides how much gate, review and merge ceremony its pull request gets. The model itself — dimensions, tiers, the gate matrix — lives in [Tag-Driven Quality Gates](/docs/concepts/tag-driven-gates), [PR State Flow](/docs/concepts/pr-state-flow) and the [Quality Model](/docs/reference/quality-model); this page only shows where it enters the work.

```text
refine ──► classify ──► publish-pr ──► tiered gates ──► tiered review ──► tag-driven automation
 Step 6    Step 6        Step 8         Step 8           Step 9             opt-in loop
```

1. **Refine** — you align on the story with `/pair-process-refine-story` ([Iteration](/docs/developer-journey/iteration#step-6-refine-a-user-story)).
2. **Classify** — in the same refinement, `/pair-capability-classify` writes the classification matrix into the story card and, when the project projects tags, the `risk:*` tag ([Iteration](/docs/developer-journey/iteration#classification-matrix)).
3. **Publish PR** — `/pair-capability-publish-pr` copies the story's tags onto the one PR it opens ([Execution](/docs/developer-journey/execution#closing-phase-checkpoint--pr)).
4. **Tiered gates** — the pre-merge gate reads the PR's `risk:*` tag and runs the checks for that tier; no tag runs everything ([Execution](/docs/developer-journey/execution#what-your-prs-tier-changes)).
5. **Tiered review** — review re-classifies from the actual diff, may raise the tier but never lower it, and reviewer effort scales with the tier ([Execution](/docs/developer-journey/execution#what-your-prs-tier-changes)).
6. **Tag-driven automation** — tags decide which cards the automation loop may pick up and when it stops ([Tag-Driven Automation](/docs/developer-journey/tag-driven-automation)).

## Product Lifecycle

```text
INDUCTION
└── Product Foundation & Architecture
    │
    ├── STRATEGIC INITIATIVES
    │   └── Business Value & Market Position
    │       │
    │       ├── CUSTOMER-FACING ITERATIONS
    │       │   └── User Experience & Feature Delivery
    │       │       │
    │       │       └── CONTINUOUS VALUE DELIVERY
    │       │           └── Working Software & Feedback Loops
```

| Level | Duration | Value Stream | Card Type | Focus |
|-------|----------|--------------|-----------|-------|
| Induction | One-time | Product Foundation | PRD | Product Vision, Market Fit, Technical Architecture |
| Strategic | 6-8 sprints | Business Value | Initiative | Business Objectives, Value Proposition, Roadmap |
| Iteration | 2-4 sprints | User Experience | Epic | Feature Sets, User Journeys, Integration Points |
| Execution | 1 sprint | Working Software | Story + Task | Deliverable Features, Code Quality, User Feedback |

## Card Hierarchy

```text
Initiative (Strategic Level)
├── Epic 1 (Feature Level)
│   ├── User Story 1.1
│   │   ├── Task 1.1.1

```

## Entry Points

You don't have to start at Step 1. Pick your entry point based on where you are:

| You're starting... | Start at | Skill |
| --- | --- | --- |
| A brand new project | Step 1 (PRD) | `/pair-process-specify-prd` |
| Adopting pair on an existing project | Step 2 (Bootstrap) | `/pair-process-bootstrap` |
| A new initiative or roadmap cycle | Step 3 (Initiatives) | `/pair-process-plan-initiatives` |
| A sprint planning session | Step 5 (Stories) | `/pair-process-plan-stories` |
| Picking up a story to develop | Step 8 (Implement) | `/pair-process-implement` |
| Reviewing someone's PR | Step 9 (Review) | `/pair-process-review` |

Or just run `/pair-next` — it figures out where you are and what to do next.
