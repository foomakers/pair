## Prerequisites

- [OpenAI Codex CLI](https://github.com/openai/codex) installed and authenticated
- A pair-enabled project (`pair-cli install` completed, `.pair/` directory exists)
- Node.js 18+

## Configure Agent File

Codex reads `AGENTS.md` at the repository root — the same universal bridge file used by Claude Code. pair generates it during `pair-cli install`.

### AGENTS.md

Codex automatically discovers and reads `AGENTS.md` when entering a repository. The file contains:

- Task selection algorithm (which how-to guide to follow)
- Essential commands (`pnpm install`, `pnpm test`, `pnpm lint`)
- Key references to adoption files and guidelines
- Quick rules (testing, commits, adoption checks)

```text
your-project/
├── AGENTS.md              ← Codex reads this automatically
├── .agents/
│   └── skills/            ← skill symlinks (→ .claude/skills/)
├── .pair/
│   ├── knowledge/         ← upstream guidelines (don't edit)
│   └── adoption/          ← your project decisions
└── ...
```

No additional configuration needed — Codex and Claude Code share the same entry point. Skills are distributed to `.agents/skills/` as symlinks pointing to the canonical `.claude/skills/` directory.

### The Bridge Pattern

`AGENTS.md` points to `.pair/` — the single source of truth:

```text
AGENTS.md ──→ .pair/knowledge/   (guidelines)
          ──→ .pair/adoption/    (your decisions)
```

## Use Skills

Skills are invoked as slash commands in Codex, the same way as in Claude Code:

```bash
/pair-next                    # what should I work on?
/pair-process-implement #42   # implement story #42
/pair-process-review          # review current PR
```

Codex discovers skills in `.agents/skills/` (symlinked to the canonical `.claude/skills/`). Since Codex supports the [Agent Skills](https://agentskills.io) open standard, it can read and execute pair's SKILL.md files directly.

### Common Skills

| Skill | Purpose |
|-------|---------|
| `/pair-next` | Determine next action based on project state |
| `/pair-process-implement` | Implement a story task by task |
| `/pair-process-review` | Structured code review |
| `/pair-process-refine-story` | Refine a story with acceptance criteria |

For the full catalog, see [Skills Catalog](/docs/reference/skills-catalog).

## Unattended Delivery (fan-out)

Codex is one of two harnesses that can run pair's [unattended loop](/docs/tutorials/unattended-delivery) **in-harness** — driving several cards per run by spawning a fresh subagent per phase, instead of one card per invocation.

### What has to be on

`/pair-loop` binds a realization by **probing the session it is running in**, never by checking that you are in Codex or on a given version. It looks for a multi-agent spawn/wait pair among the tools actually exposed to it:

- Codex's **first-generation** multi-agent tools are stable and on by default — a normal session already exposes them.
- The **second generation** is stable but default-off, behind its own feature flag, and lets you rename the tool namespace and set concurrency/timeout ceilings. When it is on, `/pair-loop` prefers it, and reads the namespace from the probe rather than assuming a name.

Enable nothing and the loop still works if the default-on set is exposed — a harness-side concurrency ceiling included, since the first generation declares one too and it already enters the cap arithmetic. What the second generation adds is that the ceiling and the wait timeouts become **configurable**, and the tool namespace can be renamed — which is why the loop reads the namespace from the probe instead of assuming a name.

### What you will see

Before anything is dispatched, the run prints which realization won, which primitive it bound to and why, plus the effective parallelism and which limit produced it:

```text
fan-out realization: codex-multi-agent-v1 (tier 1, codex, spawn-wait) — bound to `spawn_agent`/`wait_agent`; …
effective parallelism: 2 (bound by policy; dependency=4, policy=2, harness=8)
```

Both lines also go into the run's audit file, so a run can be reconstructed after the fact. `spawn-wait` is the third field: it says this session starts and awaits each subagent itself, and therefore owns the concurrency cap and the wait bound. The other in-harness realization pair knows — Claude Code's workflow — reports `delegated-run` instead, because there the whole run is handed over in one call. Both are probed the same way, and the loop branches on that field rather than on which product it is running in.

### Where it stops

- **No primitive exposed** — a feature turned off, a surface that does not offer the tools, an unfamiliar namespace — is not an error. The run degrades: to `pair run` (a fresh process per iteration) when that is available, otherwise to **one card plus a continue-token** you re-invoke. It never iterates several cards inside one context.
- **The audit cannot be written** stops the run outright. An unattended run with no trail is not an acceptable degraded mode.
- **Merge is never automatic** here, whatever the harness allows. Every run stops at the gate your `tech/automation.md` policy declares.

Nothing about this is Codex-specific configuration on pair's side: no `.codex/` directory is written, and skills keep arriving through `.agents/skills/` and `AGENTS.md` exactly as above.

## Workflow Tips

### Sandboxed Execution

Codex runs in a sandboxed environment by default. pair's skills work within these constraints — they read files, make code changes, and create commits through standard Git operations. No special permissions needed beyond filesystem and Git access.

### Shared Entry Point with Claude Code

Since both Codex and Claude Code read `AGENTS.md`, teams can switch between tools without any configuration changes. The project context, adoption files, and skills remain identical.

### Multi-Agent Teams

Codex reads `AGENTS.md` while Cursor reads `.cursor/rules/` and Copilot reads `.github/agents/` — all pointing to the same `.pair/` directory. The AI tool is an implementation detail; the standards are consistent.

## Verify It Works

Open Codex in your pair-enabled project and run:

```bash
/pair-next
```

**Expected output**: Codex reads `AGENTS.md`, follows the references to your adoption files, and suggests the next action. If it can't find `AGENTS.md`, check that `pair-cli install` completed successfully.
