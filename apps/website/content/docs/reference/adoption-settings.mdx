One page listing **every setting you can put in your adoption files**. `reference/configuration` covers the registry part of `pair.config.json` ([Configuration](/docs/reference/configuration)); this page covers everything else. Every section is **optional**: absent means the default in the table, never an error. A malformed section is a **HALT** naming the file and line, not a silent fallback.

<Callout type="info">
  **In your assistant, or with `/pair-assistant` (optional, Claude Code).** Default: edit the file by
  hand in your editor or assistant, then validate with the scripts below. Optional: ask [`/pair-assistant`](/docs/reference/pair-assistant#how-to-ask) ("let green cards go
  up to merge"); it shows the diff, validates with the same scripts, and writes through
  `/pair-capability-record-decision`. Rows marked **assistant** are supported by its
  [capability menu](/docs/reference/pair-assistant#capability-menu).
</Callout>

## `tech/automation.md`

Read by the delivery cycle ([`/pair-workflow-cycle`, `pair-cli run`](/docs/process-lifecycle/delivery-cycle)), `/pair-loop`, `/pair-implement-batch`, `/pair-next` and `publish-pr`. Explained in [Automated development](/docs/tutorials/automated-development#autonomy-until-gates-escalation).

| Section / key | Allowed values | Default when absent | Read by | Effect | Assistant |
| --- | --- | --- | --- | --- | --- |
| `## Autonomy` `filter` | labels, any-of | all cards | `autonomy-policy.mjs` | which cards unattended runs pick | yes |
| `## Autonomy` `assignee`, `status`, `root` | `@me` or login; canonical macrostates; issue id | all open | `autonomy-policy.mjs` | narrows the selection | yes |
| `## Autonomy` `until` | `ready`, `pr`, `merged` | `pr` | `autonomy-policy.mjs` | how far a card goes; only `merged` evaluates the merge gate | yes |
| `## Autonomy` `prepare` | `always`, `never`, `when; has: …; lacks: …` | `always` | `cycle-prepare.mjs` | who refines and breaks down a Draft card (`always` keeps a human) | yes |
| `## Autonomy` `merge` | `always`, `never`, `when; has: …; lacks: …` | `always` | `autonomy-policy.mjs`, `cycle-merge.mjs` | whether a review-approved card merges; a `when` condition escalates | yes |
| `## Eligibility` (legacy) | one label | none | `autonomy-policy.mjs` | translated to `filter:`; still honoured | yes |
| `## Auto-Advance` (legacy) | `(none)` or the eligibility tier | `(none)` | `autonomy-policy.mjs` | translated to `merge:`; still honoured | yes |
| `## Stop Predicate` | `<selector> ⇒ <condition>`, `max-iterations: N`, `idle-timeout: <seconds>` | `max-iterations: 1`; idle timeout `1800` | `pair-cli run`, `/pair-loop` | when an unattended run stops | no |
| `## Max Parallelism` | positive integer, optional `<tier>: N` | `1` | `pair-cli run --parallel`, `/pair-loop` | parallel batch ceiling | no |
| `## Audit Location` | project-relative path | `automation/loop-audit.md` under `working_path` | `/pair-loop`, `pair-cli run` | where the unattended trail is appended | no |
| `## Workflows` | `<tag> ⇒ <workflow>`, `Precedence:` | none (no tag routing) | dispatcher | opt-in per card: tag to workflow | no |
| `## Blocking Severities` | floor `Critical`, `Major` or `Minor` | `Minor` | `blocking-severities.mjs` | findings at or above the floor block | yes |
| `## Blocking Severities` `max-dispatches` | `<N> [warn\|block]` | no ceiling | `blocking-severities.mjs` | ceiling on a run's published handoffs | yes |
| `## Cycle Hooks` | `pre-<stage>`, `post-<stage>`, `pre-cycle`, `post-cycle`, `on-halt`; `timeout` (default 600, `0` off) | no hooks | `cycle-hooks.mjs` | shell commands at stage boundaries | yes |
| `## Publish-PR Hooks` | `pre-publish`, `post-publish` | no hooks | `/pair-capability-publish-pr` | commands around PR publication | yes |
| `## Harness` | harness names, `Requires: mcp` | all harnesses supported | `/pair-capability-setup-harness` | which harnesses the project supports | yes (delegated) |
| `## Model Policy` | `<risk tier>: cheap\|balanced\|frontier` | no class | `/pair-capability-setup-harness`, `workflow-profile.mjs` | model class per tier; what a profile's `model: by-tier` reads | yes (delegated) |

Validate before committing: `node .claude/skills/pair-workflow-cycle/scripts/autonomy-policy.mjs resolve`, `cycle-hooks.mjs load <file>`, `blocking-severities.mjs read <file>`. Section grammars: [Automation Policy](https://github.com/foomakers/pair/blob/main/packages/knowledge-hub/dataset/.pair/knowledge/guidelines/collaboration/automation/automation-policy.md).

| `format-check-command` | shell command | none | `publish-pr`, implement phase | formatting gate run before publishing | yes |

## `pair.config.json`

Outside the registries ([Configuration](/docs/reference/configuration)):

| Key | Allowed values | Default | Read by | Effect | Assistant |
| --- | --- | --- | --- | --- | --- |
| `skipRegistries` | registry names | none | `install`, `update` | registries left untouched, e.g. `agents` keeps your `AGENTS.md`/`CLAUDE.md` ([Quickstart](/docs/getting-started/quickstart)) | yes (`update --skip-registries`) |
| `workflowProfiles` | `default`, `files`, `inline`: named JSON profiles with `engine`, `model`, `effort`, `context` per stage | KB default: the run's engine, its default model, default effort, fresh context | `workflow-profile.mjs` | engine, model, effort and context per stage; `--profile` / `--workflow-config` override per run ([Workflow profiles](/docs/reference/configuration#workflow-profiles-workflowprofiles)) | yes |
| `engine` | `id`, `bin`, `model` maps | `claude` | `pair-cli run` | which agent engine runs ([Execution engine](/docs/reference/configuration#execution-engine-engine)) | no |
