title: Lifecycle modes
description: Three ways to run the pair lifecycle, Assisted, Semi-automatic and Automatic, which assistants support each, and when to use which.
---

The phases and the two workflows ([analysis and refinement](/docs/process-lifecycle/refinement-workflow), [delivery](/docs/process-lifecycle/delivery-workflow)) are the same in every mode. What changes is **who drives**: you, step by step; a workflow you trigger per card; or a loop that runs unattended. Pick per project, or per card.

![Three lifecycle modes compared across the refinement and delivery workflows](/diagrams/lifecycle-modes.svg)

*Figure: move right along a row and the human disappears from the loop; move down and the same mode applies to delivery instead of refinement.*

## Assisted

**You run every step and the AI assists at each one.** PRD, bootstrap, planning, refinement, implementation and review are each one skill you invoke, in the order the [phases](/docs/process-lifecycle/phases) give. Use it while learning pair, on a new or high-risk project, or when you want to read and approve every decision.

## Semi-automatic

**You steer the planning; a workflow runs the stages and stops at checkpoints for you.**

- **Refinement**: `/pair-refine-batch` refines a set of Draft cards; `pair-cli run --until ready` stops a card right after refinement. Grill questions still reach you.
- **Delivery**: `/pair-workflow-cycle <id>` per card, `/pair-implement-batch` per batch, or `pair-cli run --card <id>` from a shell. The workflow runs implement, independent verify and remediation, then stops at the review-approved PR or at an [escalation](/docs/concepts/glossary#escalation).

Use it when the project is set up, the backlog is known, and you want independent verification without running each stage by hand. Recipe: [Deliver a card](/docs/guides/deliver-a-card).

## Automatic

**pair selects cards and delivers them without you, inside the gates you set.**

- **Drivers**: `/pair-loop` in a Claude Code session, or `pair-cli run --root <id> --parallel <n> --watch` as a daemon on any [engine](/docs/concepts/glossary#engine).
- **Gates**: `until` (`ready`, `pr`, `merged`), `prepare` and `merge` decide how far a card goes; an escalation hands a card back to a human.
- **Safe defaults**: nothing merges and no Draft card is prepared unattended until you declare it.

Use it when classification and gates are trusted and the backlog is mostly low-risk. Read [what it does and does not protect you from](/docs/tutorials/automated-development#safety-what-this-does-and-does-not-protect-you-from) before the first unattended run. Walkthrough: [Automated development](/docs/tutorials/automated-development); every key: [Adoption settings](/docs/reference/adoption-settings#techautomationmd).

## Modes by assistant

Assisted needs only a tool that reads skills. Semi-automatic in-session needs a [harness](/docs/concepts/glossary#harness) with subagents; from a shell, `pair-cli run` needs an engine. Automatic needs an engine.

| Mode | Claude Code | Codex | pi | opencode | Cursor | GitHub Copilot | Windsurf |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Assisted | yes | yes | yes | yes | yes | yes | yes |
| Semi-automatic, in session (`/pair-workflow-cycle`) | yes | yes | yes, with pi-subagents | no | no | no | no |
| Semi-automatic and Automatic, from a shell (`pair-cli run`) | yes (`claude -p`) | yes | yes | yes | no | no | no |
| Automatic, in session (`/pair-loop` with the batch workflows) | yes | degraded, one card per run | degraded, one card per run | no | no | no | no |

"Degraded" means the skill runs one card and prints a continue-token for the next invocation. The harness and engine layer is explained in [Harnesses and engines](/docs/integrations/adding-a-harness); per-tool setup in [AI coding tools](/docs/integrations).

## Modes by workflow

| Mode | Workflow | Who triggers | What runs | Where it stops | Config |
| --- | --- | --- | --- | --- | --- |
| Assisted | Refinement | you, per skill | `/pair-process-brainstorm`, `-plan-stories`, `-refine-story`, `-plan-tasks` | after each skill | none |
| Assisted | Delivery | you, per skill | `/pair-process-implement`, `/pair-process-review` | after each skill | none |
| Semi-automatic | Refinement | you, per batch | `/pair-refine-batch`, `pair-cli run --until ready` | Ready, or a grill question | `prepare` |
| Semi-automatic | Delivery | you, per card or batch | `/pair-workflow-cycle`, `/pair-implement-batch`, `pair-cli run --card` | review-approved PR, escalation | `until`, Blocking Severities |
| Automatic | Refinement | the loop | `prepare` gate `never` or `when` | escalation (`needs-review`) | `prepare` |
| Automatic | Delivery | the loop or daemon | `/pair-loop`, `pair-cli run --root --parallel --watch` | gates `until` and `merge`, escalation | `## Autonomy` |

## Which to use

| Situation | Mode |
| --- | --- |
| New to pair, new project, high-risk work | Assisted |
| Known backlog, you want to trigger and review per card | Semi-automatic |
| Mature gates, trusted low-risk backlog, no one watching | Automatic |

Modes mix: plan Assisted, deliver Semi-automatic, and hand the green cards to Automatic. Configuring the gates is a guide: [Autonomy and per-stage engine and model](/docs/guides/autonomy-and-profiles).
