title: What's new in v0.5.0
description: Every novelty of v0.5.0 compared with v0.4.3, ordered by importance, with links to the explaining section and guide.
---

Ordered by importance. Upgrading from v0.4.3? Finish with [v0.4 to v0.5](/docs/migrations/v0.4-to-v0.5).

1. **Delivery workflow**: one card goes to a review-approved PR in staged, independently verified steps. See [Delivery workflow](/docs/developer-journey/delivery-workflow) and the [guide](/docs/guides/deliver-a-card).
2. **Lifecycle modes and autonomy**: assisted, semi-automatic, automatic; `until` and merge gates decide how far a run goes. See [Lifecycle modes](/docs/developer-journey/lifecycle-modes) and the [guide](/docs/guides/autonomy-and-profiles).
3. **Automated development**: `pair-cli run`, `/pair-loop` and batches deliver a backlog. See [Automated development](/docs/tutorials/automated-development) and the [guide](/docs/guides/deliver-many-cards).
4. **Marketplace plugin and `/pair-assistant`**: optional Claude Code install, update and configuration. See [`/pair-assistant`](/docs/reference/pair-assistant) and the [guide](/docs/guides/install-via-marketplace).
5. **Multi-harness**: Codex, pi, opencode and more. See [Integrations](/docs/integrations) and the [guide](/docs/guides/configure-harness).
6. **Per-stage profiles, hooks, blocking severities**: engine and model per stage, shell hooks at stage boundaries, a blocking floor. See [The delivery cycle](/docs/reference/delivery-cycle) and the [guide](/docs/guides/hooks-and-severities).
7. **Classification and risk tiers**: `risk:*` tags scale gates and review. See [Quality model](/docs/reference/quality-model) and the [guide](/docs/guides/classify-risk).
8. **Quality gates and assessments**: tiered CI, coverage ratchet, security, cost and coupling assessments. See [Quality gates configuration](/docs/reference/quality-gates-configuration) and the [guide](/docs/guides/quality-gates).
9. **Canonical states, State Mapping, DoR/DoD, Process Profile**: map any board and run a subset of the process. See [Canonical states](/docs/concepts/canonical-states) and the [guide](/docs/guides/card-states).
10. **New process skills**: refinement and brainstorm flows. See [Refinement workflow](/docs/developer-journey/refinement-workflow) and [Skill layers](/docs/developer-journey/skill-layers).
11. **PR state flow and review identity**: required `pair-review` check, native verdicts, light auto-approval. See [PR state flow](/docs/concepts/pr-state-flow) and the [guide](/docs/guides/review-identity).
12. **Tag-driven workflows**: labels route cards to workflows. See [Tag-driven automation](/docs/developer-journey/tag-driven-automation) and the [guide](/docs/guides/tag-automation).
13. **Azure DevOps and code host split**: PM tool and code host can differ. See [Azure DevOps](/docs/pm-tools/azure-devops), [Code host](/docs/concepts/code-host) and [custom PM tools](/docs/pm-tools/custom).
14. **Template overrides and package-local adoption**: per-project templates and per-package rules. See the [templates guide](/docs/guides/customize-templates) and the [monorepo guide](/docs/guides/monorepo-rules).
15. **External KB, KB version check, migration**: scaffold, package, install from a URL. See the [guide](/docs/guides/external-kb) and [update guide](/docs/guides/update-kb).
16. **Delivery metrics**: retro panel for a period. See the [guide](/docs/guides/delivery-metrics).
17. **Quick bootstrap**: start light. See [Bootstrap quick mode](/docs/getting-started/bootstrap-quick-mode).
18. **CLI robustness**: existing-repo install keeps your `AGENTS.md`/`CLAUDE.md`, backups, safer updates. See [CLI commands](/docs/reference/cli/commands) and the [guide](/docs/guides/adopt-existing-repo).
