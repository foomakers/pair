# Decision: the staleness gate reads the BINARY, and the `pair-cli` rename follows the gate's reach, not the file list

## Date

2026-08-30

## Status

Active

## Category

Convention Adoption

## Context

ADL [2026-08-25-cli-invocation-canonical-name-is-pair-cli.md](2026-08-25-cli-invocation-canonical-name-is-pair-cli.md) settled the name (`pair-cli`, no alias) and scoped the sweep from the evidence available at refinement: ten `metadata.ts` files, `reference/cli/{examples,workflows}.mdx`, `DEVELOPMENT.md`. Implementing story #449 turned the gate on and the scope did not survive contact:

1. **The real reach is 29 docs pages, not 2.** ONE measured number, used everywhere below. Run the branch's rule against `origin/main`'s docs tree (`checkDocsCommands` over `git show origin/main:<page>`, all 84 pages): **78 wrong-binary errors across 28 published docs pages**, `reference/cli/commands.mdx` and `reference/cli/update-link.mdx` the two heaviest. The sweep changed **29** pages — those 28 plus `customization/adopt.mdx`, whose single occurrence sits in a trailing comment inside a fenced tree diagram (`# Upstream guidelines (updated by pair update)`), outside the gate's positional reach and renamed for consistency rather than to satisfy the gate. Refinement's list came from grepping two files; the gate greps all of them. The story's Definition of Done requires `pnpm docs:staleness` green, so the file list is not a choice: the gate defines the scope, and the one page beyond it is named here rather than hidden in the count.
2. **Bare `pair` cannot be matched with the same shape as `pair-cli`.** `pair` is also the product's name and appears in prose on nearly every page, so widening `INVOCATION_PREFIX` naively turns the gate into a false-positive generator. Two distinct sources of noise showed up immediately, each needing a rule, not an allow-list (the previous `PROSE_WORDS` list was deleted for exactly that reason).
3. **A latent bug in the existing rule surfaced.** The span rule's leading `\s*` crosses newlines, and a CLOSING FENCE ends with a backtick — so `` ``` `` followed by a paragraph opening with "pair creates Markdown files" matched as an invocation of `creates`. Harmless while only `pair-cli` matched (paragraphs rarely open with it); 8 hard failures the moment bare `pair` counted.

## Decision

**The invocation rule captures the binary and judges it; the rename sweep follows wherever that rule reaches.**

1. `INVOCATION_PREFIX` captures the binary — `(pair-cli|pair)` — instead of pinning the literal `pair-cli`. A bare `pair <cmd>` is reported as its own error (wrong binary), **once**, and is never also reported as an unknown command. `PUBLISHED_BIN` is the single place the canonical name is written.
2. **The separator between binary and command is ONE space, not `\s+`.** A run of aligned whitespace is a diagram column, never an invocation — the four PM-tool pages map their hierarchy under a fenced heading (`pair                    Linear`), which `\s+` reads as "run `pair Linear`". This is a positional rule in the same spirit as the existing one, not a per-page exception.
3. **The span rule allows only horizontal whitespace after the opening backtick** (`` ` ``+`[ \t]*`), so a closing fence can no longer reach into the paragraph below.
4. **Scope = every surface that documents or prints an invocation**, which is the ADL's own business rule ("no dual naming") applied honestly:
   - all 11 command `metadata.ts` files (the ten enumerated **plus `run`**, added by #451 after refinement);
   - every `pair-cli` printed hint/usage/error string in `apps/pair-cli/src` and in the `scaffold-kb` templates it generates into a user's KB repo;
   - the `pair-cli update` regenerate hints printed by `packages/knowledge-hub`'s mirror tools;
   - the **shipped KB dataset**, `packages/knowledge-hub/dataset/**` — 24 spans over 7 files (`working-area.md` 12, `.skills/loop/SKILL.md` 3, `guided-quick-setup.md` 4, `tier-aware-pipeline.md` 2, `delivery-metrics.md`, `skill-conventions/README.md`, `.workflows/pair-loop.js` 1 each). This is the surface with the SHARPEST failure: a consumer runs `pair-cli install`, opens the installed `.pair/knowledge/guidelines/collaboration/working-area.md`, and every command it names is `command not found`. The dataset is the canonical source; the generated twins under root `.pair/knowledge/**` and `.claude/**` are regenerated by running the real `pair-cli update`, never hand-edited (DEVELOPMENT.md's two-step remedy);
   - `scripts/workflows/release/**` — the release scripts an operator runs by hand: printed hints (`Please run 'pair-cli install' first`), the comments describing the same invocations, and **two executable lines in `smoke-test-kb-package.sh`** that are not strings at all. Its CLI detection probed `command -v pair` and `node_modules/.bin/pair` — a binary no install creates — so on a repo where `pair-cli` IS npm-installed the script aborted with `❌ Error: pair CLI not found`; and it then ran `$PAIR_CMD kb package --output …`, a hyphen-less `kb <sub>` form (AC3's own defect class) that the real CLI answers with `error: unknown option '--output'`, since `package` is a top-level command and `kb` is not a command group. Both fixed here rather than renamed into a more confident wrong claim;
   - `qa/release-validation/*.md` — including the **expected-output assertions** ("Error message suggests using `pair-cli update` instead"), which pin the exact string `install/handler.ts` and `update/handler.ts` print and would otherwise assert output the CLI no longer produces, the `**Scope**:` lines, and the `MT-*` headings;
   - all 29 docs pages, and `DEVELOPMENT.md`.

Deliberately **out** of scope, and left bare: `scripts/smoke-tests/**` (`run_pair` is a shell function, not the binary) and `.github/workflows/*.yml` step *names* — neither is an instruction a reader executes, and neither is reachable by any gate. `qa/release-validation/*.md` was ALSO on this list until review: the exclusion was written as "headings only", but the same files carry three expected-output assertions an operator compares against the real error message, so the recorded rationale never covered them and the whole directory moved in scope (headings included, rather than leaving a mixed convention inside one file).

## Alternatives Considered

- **Keep the sweep to the ADL's file list and narrow the gate to those files**: rejected. A gate that only looks where the drift has already been fixed cannot catch the next regression — the exact failure mode this story exists to close.
- **Restrict the bare-`pair` command token to lowercase** (`[a-z]…`) to exclude `pair Linear` / `pair Filesystem`: rejected as the discriminator. It happens to work on today's four diagrams because their next word is capitalized, but the property that makes them diagrams is the *alignment*, not the capitalization; the single-space rule states the real reason and stays true for a lowercase diagram label.
- **Fix the PM-tool diagrams instead of the rule** (re-indent so `pair` is not at line start): rejected — bending documentation to a regex, and the rule would still be wrong for the next diagram.
- **Also rename bare `pair <cmd>` inside `apps/pair-cli` source comments only, leaving strings**: rejected as a half-measure — the comments describe the same invocations, and a mixed convention is what let the drift start.

## Consequences

- The diff is a string rename across `apps/website`, `apps/pair-cli`, `packages/knowledge-hub` (dataset + its regenerated twins), `qa/release-validation`, `scripts/workflows/release` and root `DEVELOPMENT.md` instead of the ~15 files the ADL predicted — mechanical and wider than the refinement estimate. It is a string rename **except in two places**, both called out for review: the staleness rule itself (`apps/website/lib/docs-staleness-check.ts`, tested) and the two executable lines in `smoke-test-kb-package.sh` (no automated gate covers that script — it is neither in `scripts/smoke-tests/**` nor in CI — so it was verified by running it against a fixture repo, see above). The story's `risk:yellow` (carried by Change/diff risk) is unchanged in kind: still multi-module, still overwhelmingly a rename.
- The dataset rename is applied to the CANONICAL source only; root `.pair/knowledge/**`, `.claude/skills/**` and `.claude/workflows/**` are the OUTPUT of a real `pair-cli update` run in this repo, and the three mirror guards (`mirror-guard`, `skill-md-mirror`, `workflow-mirror`, 630 assertions) verify it.
- Two existing assertions in `packages/knowledge-hub` (`mirror-guard.test.ts`, `skill-md-mirror.test.ts`) pin the printed regenerate hint and were updated to the new string — assertion text only, no behavior change.
- The gate now fails on a bare `pair <cmd>` in any published docs page, so a regression back to the wrong name is caught at CI, not by a reader whose copy-paste fails.
- `AC5`'s `organization.mdx` occurrence was already resolved before this story started — verified zero repo-wide; nothing to change. `AC3`'s `pair kb validate` was too, but its **sibling `pair kb package` was not**: it survived in `scripts/workflows/release/`, twice as prose and once as a live invocation. The AC was checked by grepping one command name, not the hyphen-less *form* — so the form is the check to keep, not the string.
- **Two gates were added, not one.** `docs:staleness` guards the docs tree; the CLI's OWN help text had nothing. `apps/pair-cli/src/commands/index.test.ts` now asserts every `usage` and every `examples` entry in the command registry starts with the `pair-cli` prefix (binary plus one space) — the surface where 11 of the drifted files lived, and where `run/metadata.ts` arrived from #451 carrying `usage: 'pair run [options]'` while ts:check, lint, the full suite and docs:staleness all stayed green.
- **The npx form was never actually gated.** The pre-existing prefix spelled the runner as a package *slot* followed by a still-required literal binary (`npx\s+(?:--no\s+)?@?[\w/.-]+\s+(pair-cli|pair)` plus a space), so the real documented form — `npx --no @foomakers/pair-cli <cmd>`, used on five pages — could not match at all and a misspelled command behind npx shipped silently. The suite's single npx test passed only because `--no` was swallowed as the package token. The runner is now a **prefix of the captured binary** (`npx [flags]` then optional `@scope/` and optional `@version` around it), so scope and version attach to the binary instead of hiding it.

## Adoption Impact

- `.pair/adoption/tech/infrastructure.md` — the existing canonical-name line gains the enforcement fact: the name is now checked by the website's `docs:staleness` gate, which errors on a bare `pair <cmd>`. Cross-references this ADL.
- No change to `tech-stack.md` or `way-of-working.md` — no new tool, no new process; the gate already existed and already ran in CI.
