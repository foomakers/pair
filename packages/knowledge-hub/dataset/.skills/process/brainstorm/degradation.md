# /brainstorm — Graceful Degradation (per-composition fallbacks)

Reference file for [SKILL.md](SKILL.md). The standard scenarios are in the [graceful degradation convention](../../../.pair/knowledge/guidelines/technical-standards/ai-development/skill-conventions/graceful-degradation.md) (optional skill not installed → skip that step and note it; PM tool unreachable → ask the developer directly). Read this file when a composition brainstorm expects is missing — **no case here fails the run**; the only hard stops are the [HALT Conditions](SKILL.md#halt-conditions) in SKILL.md.

- **`/grill` not installed** (Phase 1): warn and run the interview inline — one question per turn, each with a recommendation, ending only on explicit shared understanding — and assemble the blob from the answers. Discovery still completes. **The inline interview writes the same `.pair/working/` handoff** (Phase 1 item 6) — on interruption *and* on a completed blob whose run ends before phase 3 finishes, with the resolved parametrization beside it, written from here since there is no grill to offer it — so this path resumes exactly like the composed one.
- **`context-map.md` absent** (Phase 2): skip the Load/Check/Flag/Update-inline sequence and keep the scoped placement — its absence is the expected steady state, not an error, so phase 2 degrades without failing.
- **`/map-subdomains` / `/map-contexts` not installed, or no domain artifacts** (Phase 2): the blob still reaches phase 3; placement is skipped with a note, and the tree carries no subdomain/context annotation.
- **`/record-decision` not installed** (Phase 2): a flagged conflict the developer resolves by changing a registered rule cannot be formalized as a DDR — warn and record the conflict, its resolution, and the rule it changes in the **candidate tree's rationale** instead, so the decision is not lost; discovery still completes.
- **No adoption history, or an unreadable record** (Phase 3's Adoption Context Read): adoption-informed triage degrades to the pre-adoption behavior — the tree is assembled with no citations and no revisit flags. A single unparseable record is skipped with a warning naming it and the remaining records still apply; a whole unreadable tree warns once and degrades the same way. Never a HALT — full ladder in [adoption-informed-generation.md](../../../.pair/knowledge/guidelines/technical-standards/ai-development/skill-conventions/adoption-informed-generation.md).
- **`/plan-epics` / `/plan-stories` not installed** (Phase 3): present the confirmed tree with its EXTEND/CREATE proposals for manual entry rather than writing issues from here.
- **A composed step disabled by the project's [process profile](../../../.pair/knowledge/guidelines/technical-standards/ai-development/process-profiles.md)** — `define-subdomains` / `define-bounded-contexts` (Phase 2) or `plan-epics` / `plan-stories` (Phase 3): treated **exactly as not installed** (the two bullets above), skipped with a note. Never a prompt: discovery must not stop to ask about a step the developer did not name. Brainstorm applies this check itself, before composing.

## Process Profile — the direct half

The bullet above is the composition half. The other half is a **direct** `/brainstorm` invocation while the `brainstorm` step is disabled: it **warns and asks for confirmation** before running, and under `$approval: auto` it HALTs rather than running a step the project declared it does not run. Neither half fires when way-of-working carries no `## Process Profile` section — that is the `default` profile, every step enabled, this skill unchanged. Mechanics, once, for the whole corpus: [process-profile gate](../../../.pair/knowledge/guidelines/technical-standards/ai-development/skill-conventions/process-profile-gate.md).
