Workflow runs take a configuration: engine, model id and effort per step, chosen with `--config`, the `workflows` key of `pair.config.json` or `--config-override`, frozen in the run (`--reconfigure` replaces it). A workflow declares `aliases` (default engine, model, effort) that its steps cite with `alias`; a configuration defines them (`quick`: `build`, `judge`). Eight shipped configurations (six profile equivalents, base `claude` and `codex`); the key `telemetry`. The analysis script reads one run with `--run` even when another is unreadable, lists unknown token entries in a cost, and a failed run resumed without telemetry loses its closing record. A workflow run needs no `--autonomous`: the engine always runs with its own bypass arguments and only an escalation stops it; the flag is accepted and has no effect. The host sets the card's board state from the step kind through the adopted state mapping (implement, fix: In Progress; review: Review); the step key `state: <macrostate>|none` overrides it; a failed write is a warning.
