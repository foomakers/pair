Workflows described in YAML, first slice: `pair-cli run <workflow> --card <id>` runs a workflow file of typed steps (`implement`, `review`, `generic`) one step at a time in the card's worktree. New package `@pair/workflows` (grammar v1, one validator, step kinds, the `next` / `record` engine, the dispatch message); `pair-cli` is its host. The workflow is validated before any launch (`--dry-run` validates and launches nothing); each step returns a JSON result checked against its kind (`invalid-result`, `no-result`); a `review` that answers `ok` with a blocking finding or the verdict `changes-requested` is refused as `invalid-result`, and a `failed` review carries its verdict, reviewed head and findings; a failed step exits 1, a step that needs a person parks the run with the resume command, `--restart` starts over; the run directory holds the lock, the frozen workflow and `state.json`. Ships the `quick` workflow, the grammar and kind references, and a unique `Key` column in the Custom Gate Registry, whose `Key` and `Command` cells are read as Markdown writes them (inline code without its backticks, `\|` as a pipe of its cell). `pair-cli run --card <id>` with no workflow name is unchanged.
