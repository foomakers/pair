Telemetry per step of a workflow run, switched on by flag: `pair-cli run <workflow> --card <id> --telemetry` writes `telemetry.jsonl` in the run directory, one record per execution of a step (identity, kind, host, engine, model, times, tokens, outcome, attempt) and one closing record whose totals are the sums of the step records. Every token count (`read`, `cached`, `written`) carries its `source`: `measured` from the engine's usage, `estimated` from the exchanged text for a host that cannot measure (a lower bound, `cached` unknown), or `unknown`. Off by default and with `--no-telemetry`; a record that cannot be written never fails a step. New read-only skill `/pair-capability-analyze-workflow-runs`: its script answers cost, time, passes, comparison and trend, each number with its origin, never comparing measured with estimated values; without a price row cost reads "not calculated". Also: `--restart` now starts over a run whose `state.json` cannot be read, and a workflow key named like an `Object.prototype` member (`constructor`, `toString`, `__proto__`) is refused as unknown.
