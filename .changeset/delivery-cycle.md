Delivery cycle: one state machine, many realizations:

- One cycle (prepare → validate → implement → green → verify → merge) with its rules in one owner (`cycle-state.mjs`), and three realizations: in-session `/pair-workflow-cycle`, console `pair-cli run --card`, parallel `pair-implement-batch` on Claude Code. Stages talk through handoffs on disk, never the transcript, and every run resumes from its first incomplete step (#479, #480, #486, #487).
- New `/pair-workflow-cycle` drives one card one stage per subagent from Claude Code, Codex or pi. It can also enter on an existing PR for fix and review only (`$pr`, `$rounds`) (#486, #494).
- The delivery workflow is rebuilt as a coordinator plus phase skills (`red-spec`, `red-verify`, `green-fix`, `implement-phase`, `review-phase`), with deterministic seal and custody scripts. Five typed subagents ship and install to `.claude/agents/` (`pair-implementer`, `pair-reviewer`, `pair-fix-test-author`, `pair-red-contract-verifier`, `pair-contract-generator`) (#479, #480, #432).
- **Breaking (cycle contract):** a fresh card starts at test-first implement with no up-front contract, and its self-review is never recorded. Every open review finding must carry a reproducer or a failure scenario. Findings still go through the sealed prepare → validate → green path. `red-snapshot.mjs seal` requires `--static-gates` (#506, #509).
- `merge` is a cycle stage. It re-reads tier, remote head, `pair-review` and `pair-explicit-approval` live and requires the reviewed head. Only then does it squash-merge, tick the DoD, close the card with its parent cascade, move the board to Done and delete the branch. Any red leaves a comment on the card naming the condition (#490, #520).
- PM and code-host adapters, GitHub and Azure DevOps. Card operations follow `pm-tool` and PR operations follow `code-host`. The cycle scripts no longer call `gh` directly. A declared host with no adapter HALTs with `host-unsupported`, with no silent GitHub fallback. A KB extension guide shows how to add an adapter (8 methods, worked stub) (#492, #513).
- Cycle Hooks in `## Cycle Hooks`: `pre-/post-<stage>`, `pre-/post-cycle` and `on-halt`. A failing `pre-*` HALTs (`failed-hook`), `post-*` only logs, and stage hooks run in the story worktree. One executor serves both coordinators (#489, #519).
- Workflow profiles: named JSON profiles set engine, model (id, `cheap|balanced|frontier` or `by-tier`), effort and context per stage, via `pair.config.json` `workflowProfiles`, `--profile` or `--workflow-config`. They fail closed on typos and unknown stages (#488, #517).
- Adoption decides what blocks: `## Blocking Severities` (default `Critical, Major, Minor`). The hard-coded 40-dispatch cap is gone, replaced by an optional `max-dispatches: <n> [warn|block]`. `supersede` recovers any stage's last handoff (#514, #515).
- The four cycle agents default to `sonnet` (#498). A custody check can be waived only by an explicit, attributed override (#497). Machine contracts are derived from KB templates and cached by hash (#292, #318).
- KB `collaboration/automation/delivery-cycle.md`: one reference for the cycle, stages, realizations, profiles, hooks, merge and adapters, with diagrams (#493, #530).
- Fixes: every remediation group gets its own findings. red-spec refuses unformatted test artifacts. red-verify lists every gap in one rejection. implement-phase moves the card to `In Progress` and lists external AC as pending live verification. An external-only block can always be answered with `decide`. A bare `eslint` inside a package finds the shared config (#542).
- Fixes: every stage resolves with `--acHash`. A decided external blocker gets re-reviewed. The worktree checks out an existing card branch. Post-merge closure resolves the repo slug and deletes the branch through the host API. Review noise is reduced across escalations and resumes (#373, #374).
