# /pair-process-brainstorm — Graceful Degradation (per-composition fallbacks)

Reference file for [SKILL.md](./SKILL.md). The standard scenarios are in the [graceful degradation convention](../../../.pair/knowledge/guidelines/technical-standards/ai-development/skill-conventions/graceful-degradation.md) (optional skill not installed → skip that step and note it; PM tool unreachable → ask the developer directly). Read this file when a composition brainstorm expects is missing — **no case here fails the run**; the only hard stops are the [HALT Conditions](./SKILL.md#halt-conditions) in SKILL.md.

- **`/pair-capability-grill` not installed** (Phase 1): warn and run the interview inline — one question per turn, each with a recommendation, ending only on explicit shared understanding — and assemble the blob from the answers. Discovery still completes. **The inline interview writes the same `.pair/working/` handoff** (Phase 1 item 6) — on interruption *and* on a completed blob whose run ends before phase 3 finishes, with the resolved parametrization beside it, written from here since there is no grill to offer it — so this path resumes exactly like the composed one.
- **`context-map.md` absent** (Phase 2): skip the Load/Check/Flag/Update-inline sequence and keep the scoped placement — its absence is the expected steady state, not an error, so phase 2 degrades without failing.
- **`/pair-capability-map-subdomains` / `/pair-capability-map-contexts` not installed, or no domain artifacts** (Phase 2): the blob still reaches phase 3; placement is skipped with a note, and the tree carries no subdomain/context annotation.
- **`/pair-capability-record-decision` not installed** (Phase 2): a flagged conflict the developer resolves by changing a registered rule cannot be formalized as a DDR — warn and record the conflict, its resolution, and the rule it changes in the **candidate tree's rationale** instead, so the decision is not lost; discovery still completes.
- **`/pair-process-plan-epics` / `/pair-process-plan-stories` not installed** (Phase 3): present the confirmed tree with its EXTEND/CREATE proposals for manual entry rather than writing issues from here.
